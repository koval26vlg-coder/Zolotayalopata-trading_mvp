# Premarket: один видимый координатор, 6 октября 2026

## Результат и границы

Выполнен offline-инженерный этап. Новый последовательный координатор обслуживает
до двух одновременных событий одним процессом и одним global writer claim.
Гипотеза, Gate/OKX, правила отбора, измерения глубины и минимум 12 событий не менялись.
Стратегия не принята; новых рыночных наблюдений нет.

Сбор, расписания, evaluator, PnL, OOS и replay не запускались. В manifest:
`collection_enabled=false`, `schedules_resume_authorized=false`, `batch=null`.
Preflight возвращает `BLOCKED / COLLECTION_DISABLED_OFFLINE_ONLY`.
Действующий controller остаётся на
`PREMARKET_DEPTH_QUALITY_COMPLETE_INSUFFICIENT_SAMPLE`.

## Что изменено

- `trading_mvp/src/premarket_depth_coordinator.py`: один последовательный цикл,
  атомарное занятие общей блокировки, повторная проверка разрешённого технического
  состояния перед записью, отдельные файлы событий, сетка 20 секунд относительно
  открытия spot. До открытия spot не запрашивается. События с одинаковым временем
  обслуживаются детерминированно, без выбора по доходности.
- Пропущенные интервалы, сетевые ошибки, остановка, нехватка места и превышение
  бюджета раскрываются как неполный сбор. Повтор запроса в том же интервале и
  перезапись использованной папки запрещены. Частичные файлы сохраняются.
- `tools/start_premarket_depth_coordinator_visible.ps1`: отдельное видимое окно
  PowerShell `Normal / NoExit`, дочерний Python в том же окне, привязка PID и
  одноразового токена, команды статуса/остановки, watchdog и Windows Job Object.
  Потеря владельца завершает дочерний процесс; чужая блокировка не снимается.
  Запись владельца публикуется целиком и не заменяет существующего владельца.
- Старый installer прекращает установку скрытого поштучного capture до любых
  сетевых запросов или изменения планировщика. Удаление старой задачи доступно,
  но в этой работе не выполнялось. Существующие задачи остаются Disabled.
- Старый hash-bound watcher и планы сохранены как исторические доказательства.
  Его прямой CLI не переписан и не является новым маршрутом исполнения.

`COMPLETED` означает только завершение технического сбора, а не пригодность
выборки: `sample_certified=false` всегда. После будущего сбора отдельно нужны
проверка полноты окон, глубины bid/ask, идентичности и зависимости событий.
Ранее найденные 3 структурных кандидата и 2 временные группы не превращаются
в новую или достаточную выборку после исправления кода.

## Реализованные лимиты одного пакета

| Ограничение | Значение |
|---|---:|
| Событий в одном пакете | не более 2 |
| Общих market-data writers | 1 |
| Полное окно одного события | до 120 минут до и 120 минут после открытия |
| Шаг наблюдения | 20 секунд |
| HTTP-попыток на событие / пакет | 1 600 / 3 200 |
| Runtime рабочего цикла | 14 400 секунд |
| Принудительное завершение watchdog | не позже 14 405 секунд от старта дочернего процесса |
| Остановка по команде | штатно сразу между операциями; watchdog через 25 секунд |
| Ответ одного запроса | 8 MiB, исходный v6 contract |
| Сумма принятых HTTP body | 256 MiB |
| Выходные файлы пакета | 64 MiB, с резервом на итог и footer |
| Свободное место перед очередной операцией | минимум 1 GiB |

Redirects, proxies, retries и сохранение raw response body выключены. Счётчик
байтов относится к прочитанному HTTP body, а не к TLS/сетевому служебному трафику.
Неизменённый v6 даёт до 1 080 запросов на полное событие без ошибок; 1 600
остаётся потолком, а не требованием его израсходовать.

Больше двух одновременных событий не выбираются молча: пакет отклоняется по
вместимости. Если ответы слишком медленные для последовательного обслуживания
с шагом 20 секунд, пропуски фиксируются, а пакет не объявляется полным.

## Предложенный бюджет накопления, ещё не включён

Это план ограничения расходов, не созданное расписание и не обещание выборки.
Счётчик всей кампании пока не реализован; лимиты ниже нельзя считать автоматически
обеспеченными только новым per-batch координатором.

1. Первый технический пилот: один видимый пакет, максимум два заранее
   зафиксированных события. После него проверить фактическую полноту, глубину,
   задержки и расходы. До проверки пилота не расширять накопление.
2. Проверка достижимости выборки через 14 дней от будущего включения;
   абсолютный предел 42 дня. Цель не меньше 12 независимых пригодных событий;
   техническое число файлов не заменяет этот критерий.
3. Не более 24 event-captures и 24 пакетов всего. Book API: максимум 38 400
   попыток, 6 GiB body суммарно и 1.5 GiB capture-output. Каждый пакет
   дополнительно ограничен таблицей выше.
4. Если будет включён поиск расписания: не чаще одного scan в 15 минут,
   максимум 4 032 scans за 42 дня и четыре metadata-запроса на scan,
   то есть 16 128 попыток. Предлагаемый предел metadata body: 18 GiB.
   Сохранение только нормализованных записей, без сырых ответов.
5. Общий потолок кампании: 54 528 HTTP-попыток, 24 GiB body и 2 GiB output
   вместе с metadata/журналом. При достижении любого потолка остановиться с
   честным недостатком данных; бюджет не увеличивать молча.

14/42 дня и 24 capture ограничивают затраты, не меняют signal/acceptance contract.
Если независимость и наблюдаемость не достигаются, результатом будет
`INSUFFICIENT_SAMPLE`, а не принятие/отвержение доходности.

## Следующий шаг без повторного approval-loop

При дальнейшем продолжении в том же scope нужен технический, а не словесный
переход: реализовать общий budget ledger и discovery-to-batch диспетчер без
старого скрытого `_spawn_capture`, связать будущий immutable batch со свежим
guard, проверить missed/over-capacity события и выполнить технический rebind.
До этого нельзя считать весь автоматический цикл готовым или включать старый
scan в обход нового координатора. В этой подтверждённой offline-работе это
следующий этап, а не разрешённый сейчас сетевой пилот.

Безопасная текущая проверка:

```powershell
pwsh -NoProfile -File tools/start_premarket_depth_coordinator_visible.ps1 -PreflightOnly
pwsh -NoProfile -File tools/start_premarket_depth_coordinator_visible.ps1 -Status -RunId premarket_depth_offline_verification
```

Для реально выбранного будущего run остановка выполняется тем же launcher
с `-Stop -RunId <exact_run_id>`. При неоднозначном запуске сначала статус,
а не повторный запуск. Сейчас run не выбран и не запущен.
