## Принцип отбора

Retail-edge бывает четырёх видов: (1) оплата за услугу (carry/премии), (2) события с предсказуемым механизмом, (3) ниши с ёмкостью ниже институционального порога, (4) асимметрия издержек. Гипотезы ниже ранжированы по `prior × дешевизна проверки`. Цель портфельная: 3–5 слабо коррелированных краёв, а не один грааль.

Правило активации: гипотеза переходит из backlog в работу только через запись в experiment ledger (канал-источник, датасет, конфиг, гейты, вердикт). Одновременно в активной работе не более двух гипотез — иначе ни одна не доходит до вердикта.

## H1. Кросс-секционный momentum на дневных данных

- **Категория:** ниша (ёмкость ниже институционального порога) + документированная аномалия.
- **Механизм:** монеты с лучшей доходностью за 1–3 месяца продолжают опережать худшие на горизонте недель. Самая устойчивая аномалия в академической литературе по крипте; низкая частота амортизирует издержки.
- **Конструкция для проверки:** ранжирование universe по 30/60/90-дневной доходности → long верхний дециль / short нижний дециль через перпы → ребаланс раз в неделю. Обязательно включить funding cost шортов и издержки ребаланса в replay.
- **Данные:** дневные OHLCV klines (public REST MEXC/Gate/Bybit/OKX), история 2+ года; funding history для перпов. **Не требует WS-коллектора вообще** — самая дешёвая по данным гипотеза backlog. Один REST-скрипт, часы сбора, мегабайты хранения.
- **Решение пользователя 2026-07-02:** расширенный universe разрешён. Исходная задумка «не на Binance Spot» сохраняется как именованный базовый вариант: прогоны делаются в двух конфигурациях (`universe=non_binance_baseline` и `universe=extended`), результаты помечаются явно и сравниваются.
- **Гейты/kill:** стандартная матрица goal v2. Специфично: OOS по времени (train 2024–2025, test 2026), деградация после издержек < 50% in-sample эффекта, минимум 30 недельных ребалансов в OOS. Kill: net expectancy ≤ 0 после funding+fees, либо весь эффект в 1–2 монетах (концентрационный тест).
- **Приоритет: P0 — можно начинать немедленно, параллельно ремонту коллектора.**

## H2. Cross-exchange funding carry

- **Категория:** оплата за услугу.
- **Механизм:** funding-ставки на одну монету расходятся между биржами (второй эшелон медленнее арбитражится). Шорт перпа там, где funding аномально высок, лонг перпа/спот там, где нормален. Delta-neutral; доход = спред ставок − издержки − basis-риск.
- **Данные:** funding rate history по 3–4 биржам (MEXC, Gate, Bybit, OKX — публичные REST endpoints, у большинства есть история), mark/index prices, спот-цены. Multiweek forward-сбор + исторические endpoints. REST, низкая частота — устойчив к сети, можно собирать с домашней машины уже сейчас.
- **Гейты/kill:** cost gate с E0-ставками (без E0 ветка почти наверняка kill by construction — сначала E0); минимум 4 недели данных и 50+ эпизодов спреда выше порога; стресс: обе ноги по худшей цене, funding решает развернуться до закрытия. Kill: p95 спреда ставок ≤ round-trip cost обеих ног + safety margin.
- **Зависимости:** E0 (fee evidence). Расширяет существующую funding-ветку (`funding.py`, `basis.py`, TRADING_FUNDING_* контур) — большая часть кода уже есть.
- **Приоритет: P0 — запускать multiweek сбор сразу после E0.**

- **Статус:** заблокирована воротами 2026-06-28 (`rank_eligible=0` на retail-издержках). Разблокируется только через E0.
- **Действие:** после E0 повторить 7d final-review с задокументированными maker/VIP-ставками; при проходе cost gate — multiweek collection по плану goal v2, приоритет ветки 1.
- **Kill:** прежние kill rules; если и на maker-модели `rank_eligible=0` — честно закрыть ветку на текущем universe.
- **Приоритет: P0 (условно — сразу после E0).**

## H4. Token unlock event shorts

- **Категория:** событие с предсказуемым механизмом.
- **Механизм:** крупные разлоки (>0.5–1% circulating supply) создают навес предложения; документировано отрицательное среднее движение в окне до/вокруг разлока. Исполнение: шорт перпа за N дней до события, закрытие в/после события.
- **Данные:** календарь разлоков (публичные агрегаторы типа Tokenomist/CryptoRank — зафиксировать источник и методологию в ledger), дневные/часовые klines, наличие перпа на MEXC/Gate/Bybit, funding cost шорта за период удержания. История событий 2+ года, цель — 100+ событий для event study.
- **Гейты/kill:** event study с контрольной группой (те же монеты вне окон разлока); OOS по времени; стресс на funding-спайки против шорта. Kill: средний эффект после издержек и funding ≤ 0, либо эффект существует только до 2024 (decay), либо выживает < 30 событий после фильтров ликвидности.
- **Решение пользователя 2026-07-02:** как в H1 — расширенный universe разрешён, non-Binance остаётся именованным базовым вариантом для сравнения.
- **Приоритет: P1 — после запуска H1/H2, т.к. требует сборки календаря событий.**

## H5. Listing-эффекты второго порядка

- **Категория:** событие + информационная гонка (секунды-минуты, не микросекунды — retail-выигрываемая).
- **Механизм:** анонс листинга на Binance/Coinbase → монета, уже торгуемая на MEXC/Gate, репрайсится с задержкой. Покупка в первые секунды после анонса, выход по правилу времени/цели.
- **Данные:** (а) исторический архив анонсов Binance/Coinbase с точными timestamp; (б) 1m klines MEXC/Gate вокруг 50+ исторических событий — public REST, дешёво. Для forward-фазы: пайплайн мониторинга анонсов (у проекта уже есть агентная инфраструктура).
- **Гейты/kill:** event window controls из goal v2 обязательны; latency-модель: вход не раньше T+5–10 сек от анонса, консервативный slippage на тонком стакане; стресс: вход по худшей цене окна. Kill: эффект исчезает при реалистичной задержке входа, либо ёмкость < минимального нотионала после slippage-модели.
- **Приоритет: P1.**
- **Примечание:** это старая идея проекта («listing/event effects» — приоритет 3 в goal v2), здесь она конкретизирована до тестируемого протокола.

## H6. Депеги стейблкоинов / миграции токенов (оппортунистическая)

- **Категория:** событие с сильной механикой, редкое.
- **Механизм:** mean reversion мелких депегов обеспеченных стейблов; принудительные конвертации при миграциях.
- **Решение:** не тратить активные циклы. Завести watch-правило (алерт при |peg − 1| > порога) и playbook-документ; проверять исторические эпизоды только когда H1–H4 дадут вердикты.
- **Приоритет: P2 (watch-only).**

## H7. Volatility risk premium (Deribit, delta-hedged short options)

- **Категория:** оплата за услугу; документированная премия (IV > RV систематически).
- **Почему отложено:** требует маржи и live-исполнения по построению, толстые хвосты (один взрыв съедает месяцы премий), выходит за текущие safety boundaries проекта.
- **Действие сейчас:** только бумажное исследование на публичных данных Deribit (DVOL, IV vs RV спред) без какого-либо исполнения; полноценная активация — отдельное решение пользователя после первого принятого кандидата из H1–H4.
- **Приоритет: P2 (research note only).**

## H8. On-chain / sentiment сигналы

- **Категория:** информационная; усилитель для H1/H4/H5, не самостоятельный edge.
- **Механизм:** притоки на биржи, smart-money кошельки, активность анонсов — как фильтр/фича поверх событийных веток.
- **Действие:** не строить отдельную ветку; при работе над H4/H5 оценивать 1–2 дешёвых публичных сигнала как дополнительную фичу с обязательным ablation-тестом (edge должен существовать и без фичи).
- **Приоритет: P2.**

## H9. Airdrop / points farming, конкурсы, рефералки (вне торгового контура)

- **Статус:** вне gate matrix и вне trading_mvp по построению (кастоди/KYC/юридические вопросы — та же граница, что у P2P/off-ramp).
