# Техническая привязка экономической базы и доказательств

9 октября 2026. Исправление реализации без изменения гипотез, периодов, расходов,
риска, порогов или набора из 20 моделей. Старые снимки не переписаны.

## Что исправлено

- Концентрация положительного результата считается по `economic_base_id`, не по тикеру.
  Четыре названия одного золота дают 100% концентрации, а не 25%.
- Без привязки хотя бы одной сделки значение концентрации базы отсутствует.
  Даже убыточная сделка с неизвестной базой делает проверку неполной.
- Привязка берётся из отдельного файла доказательств, связанного с планом, моделью,
  текущим runtime и полными описаниями выбранных входных файлов. Тикер не угадывается.
- Привязка должна быть известна к входу и действовать до выхода. Пересекающиеся
  записи и противоречие одной идентичности разным экономическим базам запрещены.
- Для золота, DAX, Aave USDC и BTC/ETH-опционов проверяется фиксированная база модели.
- Обычный и стрессовый расчёты обоих путей получают одинаковую привязку перед статистикой.
- Изменение доказательств блокирует старый результат даже при прежнем числе строк.
  Отдельная команда report повторно проверяет доказательства без пересчёта сделок.
- Значения `UNSEEN_CERTIFIED` и `EXECUTABLE_CERTIFIED` сами по себе не открывают
  статус кандидата. Строки, числа и заявления в JSON не заменяют проверку.

## Что это не доказывает

`BOUND_NOT_INDEPENDENTLY_CERTIFIED` означает только проверенную связь файлов,
сроков и области действия. Хэш не подтверждает истинность содержимого источника.
Датированные записи идентичности пока являются связанными утверждениями, а не
независимой проверкой их смысла. Недостоверные разные identity_key всё ещё могут
заявлять разные базы: это задача следующего содержательного аудита.

Независимая сертификация отсутствия просмотра OOS и исполнимости не реализована.
Оба флага остаются false. Не создано ни одного настоящего сертификата или
подготовленного торгового входа. Все 20 моделей остаются BLOCKED_DATA, без
расчёта доходности реальной истории и без новых вердиктов ACCEPT/REJECT.
Шесть конфликтов критериев из v20 сохраняются; исправление их не маскирует.

## Проверка

- RED: 216 тестов, ровно три ожидаемых падения воспроизводят ошибку концентрации.
  `STOPPED_INCOMPLETE` этого прогона относится к намеренно падающим unit-тестам,
  не к сбору рынка. Старый namespace не перезапускался.
- Промежуточный GREEN: 240 тестов прошли, после чего добавлены две сквозные проверки.
- Финальный видимый запуск `history_verify_v21_final_20261009`: 242 теста,
  0 ошибок, 0 падений. Все 213 прежних тестов и 29 новых проверок выполнены.
- Проверены владелец видимого терминала, runtime каждого прогона и неизменность плана.
  Хэши файлов v20 сверяются без запуска старого verifier против нового runtime.
- Сеть, collector, реальные исторические PnL/OOS, расписания и финансовые действия
  не запускались. Финансовые значения в тестах только синтетические.

Проверка сохранённого результата, без торговли и без пересчёта рынка:

```powershell
$env:PYTHONDONTWRITEBYTECODE = '1'
& 'C:\Program Files\Python313\python.exe' docs\analysis\channel-strategy-validation-20261006\continuation-v21\verify_checkpoint.py
```

## Следующий шаг

Содержательная проверка уже имеющихся доказательств: история использования данных,
проверка идентичности экономической базы и фактических условий исполнения.
Нельзя выдавать новый хэш или подписанный человеком текст за независимый OOS.
При отсутствии доказательств сохранить блокер, не запускать повторные probes.
Изменения критериев для шести несовместимых моделей остаются отдельным решением.

[readiness.json](readiness.json) перечисляет все 20 моделей с текущими техническими
ограничениями. [runtime-rebind.json](runtime-rebind.json) связывает исправление
с предыдущим runtime и финальными тестами. Подробная неизменённая матрица источников
и конфликтов: [v20](../continuation-v20/matrix.md).
