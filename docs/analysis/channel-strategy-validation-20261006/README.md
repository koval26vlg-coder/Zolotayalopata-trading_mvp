## Как запускать

Все команды выполняются из `C:\Users\koval\Documents\ZolotyayLopata`.
Launcher самостоятельно открывает видимый PowerShell, показывает команды состояния и остановки.

```powershell
pwsh -NoProfile -File tools\run_channel_strategy_validation_visible.ps1 -PreflightOnly
pwsh -NoProfile -File tools\run_channel_strategy_validation_visible.ps1 -Stage verify -MaxRuntimeSec 300
pwsh -NoProfile -File tools\run_channel_strategy_validation_visible.ps1 -Stage inventory
pwsh -NoProfile -File tools\run_channel_strategy_validation_visible.ps1 -Stage validate -InputManifest C:\historical-input\gate.channel-input.json
pwsh -NoProfile -File tools\run_channel_strategy_validation_visible.ps1 -Stage pipeline -InputManifest C:\historical-input\gate.channel-input.json
pwsh -NoProfile -File tools\run_channel_strategy_validation_visible.ps1 -Stage report -EvaluationPath C:\historical-result\evaluation.json -InputManifest C:\historical-input\gate.channel-input.json
pwsh -NoProfile -File tools\run_channel_strategy_validation_visible.ps1 -Status -RunId <returned-run-id>
pwsh -NoProfile -File tools\run_channel_strategy_validation_visible.ps1 -Stop -RunId <returned-run-id>
```

`PreflightOnly` проверяет frozen plan и показывает code binding, не создавая namespace или торговые результаты.
`inventory` не читает произвольные старые partial captures: ищет только явно подготовленные manifest.
`validate` проверяет данные, но не считает сделки. `evaluate` создаёт только результаты новой программы.
`report` проверяет provenance существующего результата; `pipeline` выполняет стадии последовательно.

Операционные файлы и скачанные архивы находятся в `runs/<run-id>` и исключены из Git.
Проверенные итоговые снимки сохраняются отдельно; старые runtime-поколения не выдаются за текущие.

## Формат входа

Manifest имеет `schema=channel_input_v1`, `status=COMPLETE`, точный `plan_hash`, `datasets`
и `manifest_hash`. Хэш вычисляется канонической функцией `canonical_hash` от объекта без
самого поля хэша. Кодировка JSON/JSONL UTF-8, UTC timestamps с часовым поясом либо epoch seconds.

Каждый dataset содержит:

```json
{
  "id": "gate-btc-1h",
  "kind": "bars_1h",
  "market": "gate",
  "model_ids": ["relative_strength"],
  "status": "COMPLETE",
  "source_access": "PUBLIC",
  "path": "gate-btc-1h.jsonl",
  "rows": 1,
  "sha256": "sha256-of-actual-file"
}
```

Это описание структуры, НЕ готовый вход. Неверный хэш или неполный набор будет отклонён.
Пути файлов относительны каталогу manifest и не могут выходить из него через `..` или ссылки.
Все входы хэшируются до и после чтения. Изменение цены при том же числе строк меняет binding.

Список обязательных полей каждого типа задан в `data.py`. Общие поля: `ts`, `available_at`, `symbol`.
`symbol` в криптосвечах означает проверенную базу, например BTC, не неоднозначный тикер другой монеты.
В опционах это уникальный контракт; в on-chain данных дополнительно обязателен адрес токена.
Для нескольких операций в один timestamp нужен уникальный `sequence`.

- `available_at` у свечи не раньше её закрытия. Внутренние разрывы криптосвечей отклоняются.
- PIT universe содержит все кандидаты и 30 прошлых дневных оборотов, известный тогда тип актива,
  историческую активность и выбранный месячный состав. Сегодняшний список монет не подходит.
- Котировки содержат bid/ask, доступные количества и датированную модель комиссий.
- Пары требуют раздельных комиссий и impact обеих ног, признака проверенного пересчёта в base units,
  типа инструмента и площадки каждой ноги. Funding содержит реальную цену расчёта выплаты.
- Опционы требуют реальных bid/ask, размеров контрактов и проверенного перевода расчётов в USD.
  Синтетические премии из BTC/ETH свечей не допускаются.
- Calendar содержит официальные session open/close с timezone и временем доступности;
  для гэпов нужен предыдущий regular-session close с учётом корпоративных действий.
- Short акций требует доказательств доступности займа и расходов. Это только моделирование.
- Aave требует liquidity index, цену USDC, gas и доступность вывода; APY одного дня недостаточно.
- DEX требует наблюдаемую покупку, следующую допустимую block quote, gas, размер и продаваемость.

## Допущения реализации

Условия ниже уточняют неоднозначные детали до расчёта доходностей, не являются подбором параметров.

1. Опционные недели начинаются в понедельник 00:00 UTC; при отсутствии пригодной цепочки вход пропускается.
2. Семь уровней grid фиксируются на неделю. Начальный inventory составляет половину бюджета,
   оставшаяся половина обслуживает три нижние заявки. Проданная верхняя порция может быть выкуплена
   на предыдущем уровне. Диапазон не переносится. Проверяются реальные bid/ask и доступный размер.
3. Свечные оценки используют явно объявленные в plan 10 bps комиссии и 10 bps неблагоприятного
   исполнения на каждую сторону. Это исследовательские допущения, не подтверждённые текущие тарифы.
4. Деривативы допускаются в расчёт только с полным резервом. Если минимальный контракт не помещается
   в бюджет, дробный вымышленный контракт не создаётся.
5. Нетронутость финального периода по умолчанию неизвестна. Ни дата нового файла, ни новый SHA
   не дают сертификат независимого OOS. Текущий runner не выдаёт кандидатский статус автоматически
   по одному пользовательскому полю `unseen=true`; необходим отдельный содержательный аудит доказательств.

## Ограничения и незавершённая часть программы

Полная историческая проверка **ещё не выполнена**. Не выполнены:

1. Восстановление месячного Gate universe с удалёнными активами и точным quote-turnover.
2. Полная загрузка/нормализация 2023-2026 и проверка реальных market-specific входов.
3. Проверка опционных цепочек, американских акций, DAX, золота и on-chain наборов на полных периодах.
4. Независимый аудит исполнения и истории просмотра данных, необходимый для кандидатского вердикта.

Текущий результат фиксирует инженерный первый этап и частичный аудит доступности, а не завершение всей научной программы.
Положительных или отрицательных выводов о доходности новых моделей нет.

Проверка условного объединения выполнена; реальное время доступности котировок
по меткам архива не доказано. Следующий шаг: датированные единицы контрактов и
расходы; при отсутствии доказательств закрыть данный вход как BLOCKED_DATA,
не начинать массовые загрузки. Полнота шести gzip уже подтверждена. Для MEXC
история исполнимых котировок остаётся неподтверждённой. Исторический PIT-состав,
единицы контрактов и датированные расходы остаются обязательными зависимостями
перед реальным бэктестом. Частичные mark-price файлы не считать полными.
Неполные или закрытые старые результаты не использовать как вход новой программы.
Уже завершённые поиски источников не повторять без новых сведений. Отдельно проверить
совместимость общих критериев со всеми моделями, не меняя пороги задним числом.

Listing Momentum, paused premarket-depth, старые readiness/policy и terminal-вердикты не изменены.
Private API, реальные ордера, платные данные и расписания не использовались.
