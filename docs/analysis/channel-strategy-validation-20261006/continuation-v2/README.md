## Проверяемые артефакты

- `archive-discovery-summary.json`: границы локального обхода, количества, хэши двух прочитанных PIT-файлов и ссылка с SHA256 на полный локальный список.
- `gate-history-audit.json`: десять фиксированных запросов, HTTP-статусы, размеры, SHA256 ответов и доступные диапазоны.
- `volume-reconciliation.json`: сравнение объёмов и OHLC по каждому из восьми дней, с хэшами исходных REST/CSV-файлов.
- `catalog-audit.json`: три дополнительных запроса каталога. Пагинация остановлена сразу при несовпадении Prefix/Marker.
- `verification.json`: 72 теста, 0 ошибок, 0 падений; включает исходные 53 и 19 новых проверок.

Полные локальные артефакты и сырые публичные ответы сохраняются в игнорируемой Git папке `../runs/`.
В Git опубликованы сводки и хэши, а не многогигабайтный старый архив.
Инвентаризация перечисляла имена и размеры, но не читала цены/PnL старых OOS и не запускала старые evaluator.

## Следующий ограниченный шаг

1. Проверить официальный интерфейс экспорта Gate и источники событий листинга/делистинга на возможность восстановить исторические пары. Существующий S3-подобный endpoint с неработающим prefix больше не перебирать вслепую.
2. Для найденных пар установить доступность на начало каждого месяца и тип актива на ту дату. Наличие файла за месяц само по себе не доказывает доступность в его первый день.
3. Получить предыдущие 30 полных UTC-дней точного USDT-оборота. Уже подтверждён рабочий источник дневных значений для BTC/ETH, но его пригодность для снятых с торгов пар ещё не проверена.
4. Только после этого нормализовать полный вход первой очереди и выполнить фиксированные модели 1–4. До этого их статус остаётся `BLOCKED_DATA`, а не отрицательным результатом стратегии.

Не заменять исторический состав сегодняшним топом. Не сдвигать тестовые периоды и не сокращать universe ради красивого результата.
Если полный бесплатный набор доказать не удастся, это будет конечный `BLOCKED_DATA` данного входа, а не повод ждать месяцы нового сбора.
