# Исторические входы: состав Gate и опционные архивы OKX

Проверено 6 октября 2026. Это законченная ограниченная проверка источников,
а не backtest и не новый вердикт о прибыльности. Правила всех 20 моделей сохранены.

## Что изменилось

1. Ограниченный поиск исторического состава Gate завершён для текущей итерации.
   Вход остаётся `BLOCKED_DATA`: полный состав, исторические типы монет и полные
   30-дневные обороты всех кандидатов не подтверждены. Повторять те же пробы не нужно.
2. Найден и фактически проверен публичный путь к архивам опционных стаканов OKX.
   Он не зависит от состава Gate и подходит для следующего этапа моделей 11–13.
3. Подготовлен `model-input-queue.json`: все 20 моделей присутствуют, статус проверки
   источника отделён от готовности данных и от результата стратегии.

## Gate: что именно проверено

Документация Tardis заявляет сбор всех пар Gate с 9 июня 2022 года и даёт endpoint
`https://api.tardis.dev/v1/exchanges/gate-io`. Он ответил HTTP 200, но объявил размер
1 945 579 байт. Лимит **диагностической пробы** в замороженном контракте программы
равен 1 000 000 байт на ответ. Тело не читалось, повтор не выполнялся.

Это **не доказательство отсутствия бесплатного каталога**, не пустой список и не
причина отвергать стратегии. Источник найден, но его полный ответ в этой пробе
не проверен. Даже полный список `availableSymbols` описывает покрытие поставщика:
`availableSince` нельзя без отдельного основания превращать в дату листинга,
`availableTo` в дату делистинга, а `type=spot` в исторический тип самого актива.
Отсутствующая дата окончания не доказывает, что пара продолжала торговаться.

Предыдущие доказательства сохраняются в `../continuation-v3/`: архивы снятых с торгов
TRC/EYWA существуют, оборот полученных сделок восстановим, но сегодняшний экспортный
список и согласие двух неполных архивов не доказывают полноту исторического состава.
Старые файлы, отсутствующие интервалы и закрытые ветки не переписывались.

Модели 1–6 и 14 имеют общую нерешённую зависимость `pit_universe`. Их входы пока
отложены. Разморозка возможна при появлении нового проверяемого источника, а не при
повторении уже выполненных запросов или подмене состава сегодняшними победителями.

## OKX: новый проверенный путь

Официальная форма исторических данных содержит опционные стаканы BTC-USD и ETH-USD.
В опубликованном JavaScript формы найден публичный запрос каталога:

`POST https://www.okx.com/priapi/v5/broker/public/trade-data/download-link`

Несмотря на часть имени `priapi`, использован именно маршрут `broker/public`,
без входа, cookies, ключей или заголовка Authorization. Личные API не вызывались.
Сначала форма в браузере вернула список семи BTC-файлов за 3–9 января 2025 года.
Эта проба формы только получила ссылки, не скачивала сами архивы.

Затем отдельный видимый скрипт сделал ровно **три запроса**: один к каталогу за
6 января 2025 года и два GET с `Range: bytes=0-999999`. Даты запроса вычисляются
в UTC, независимо от часового пояса браузера.

| Проверка | BTC-USD | ETH-USD |
|---|---:|---:|
| Архив | 06.01.2025, optionchain, L2, 400 уровней | тот же день и формат |
| Полный сжатый размер из Content-Range, байт | 255 036 575 | 250 576 137 |
| Загружено для пробы, байт | 1 000 000 | 1 000 000 |
| HTTP | 206, диапазон подтверждён | 206, диапазон подтверждён |
| Первый контракт в префиксе | BTC-USD-250106-100000-C | ETH-USD-250106-3000-C |
| Тип первой записи | snapshot | snapshot |
| Уровней bid / ask в первой записи | 3 / 12 | 2 / 0 |

Первый ответ каталога: HTTP 200, 1 053 байта. Итого получено **2 001 053 байта**.
Автоматических повторов, переходов по redirect и загрузки целых архивов не было.
Распаковка каждой пробы ограничена 8 MiB памяти. TAR не извлекается на диск;
проверяется контрольная сумма заголовка, опасные имена отклоняются.

В обеих пробах наблюдаются поля `instId`, `action`, `ts`, `bids`, `asks`.
Это реальная история стакана, а не премии, рассчитанные из свечей BTC/ETH.
Но первые контракты являются call с близким истечением: это **только проверка схемы**,
не выбранные для модели put около 30 DTE. ETH-проба односторонняя, не содержит
исполняемой ask. Пропущенная ask не заменялась bid, mid или расчётной премией.

`body.complete=true` означает полноту **ответа на Range**, не всего архива.
Проверка gzip до конца, полный TAR, вся цепочка, все понедельники и выходы через
7 дней не проверены. Поэтому `archive_complete=false`, `option_chain_complete=false`
и `evaluation_eligible=false`. Частичный файл не может стать входом evaluator.

## Реализация и проверка

- `gate_metadata.py`: один публичный запрос, строгая схема, уникальность идентификаторов,
  UTC и интервалы; никакой автоматической сертификации исторического состава.
- `okx_history.py`: точный каталог BTC/ETH, привязка даты/имени/хоста, подтверждённый
  HTTP 206, лимит распаковки, проверка TAR и явный статус частичного архива.
- Новые этапы доступны через существующие runner и видимый launcher, включая
  `PreflightOnly`, `Status` и `Stop`.
- Первый тестовый прогон: 91 тест. Итоговый: **99 тестов, 0 падений, 0 ошибок**.
  Проверялся новый пакет, не весь legacy-репозиторий.
- Все прогоны выполнялись последовательно, в видимом PowerShell, с подтверждённым
  владельцем терминала и одним global writer. Лимит каждого прогона: 300 секунд.
- Сырые ответы и префиксы сохранены локально в игнорируемом `../runs/`.
  Здесь опубликованы отчёты, контрольные суммы и сведения о завершении.
- Listing Momentum, premarket-depth, расписания и чужие изменения не затрагивались.

## Следующий шаг

**Один ограниченный этап подготовки полного опционного входа**, а не очередной
повтор поиска Gate и не загрузка всех лет сразу:

1. На подтверждённом формате создать потоковый reader полного TAR/gzip с контролем
   завершения, snapshot/update, времени, порядка сообщений и пустых сторон стакана.
2. Связать контракт, валюту премии/расчётов, множитель, комиссию и underlying quote
   с историческими источниками. Нельзя переносить сегодняшние спецификации на 2025 год.
3. Сначала зафиксировать ограниченный бюджет одного полного файла/пакета и namespace.
   Полные файлы в сотни MB не выдавать за диагностическую пробу с лимитом 1 MB;
   не скачивать их скрыто и не обходить бюджет серией диапазонных запросов.
4. Проверить настоящие put около 30 DTE, доступность входа в понедельник и выхода
   через 7 дней. Только полный, проверенный и привязанный к хэшам набор передавать
   моделям 11–13. Неполное покрытие 2023 года не скрывать сдвигом начала периода.

Официальная страница заявляет L2-архив с марта 2023 года, поэтому январь–февраль
2023 и warmup остаются отдельным ограничением фиксированного плана. Tardis предлагает
бесплатные файлы первого дня каждого месяца; этого само по себе недостаточно для
еженедельного входа и выхода через 7 дней. Платные подписки не приобретались.

Текущий итог программы не изменился: нет принятой стратегии и нет рассчитанной
прибыльности на новых исторических входах. Есть подтверждённый следующий источник.
