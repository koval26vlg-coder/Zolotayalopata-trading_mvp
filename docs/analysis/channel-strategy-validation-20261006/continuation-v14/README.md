# Следование кошелькам: пригодность исторических данных

8 октября 2026. Модель 20 `wallet_follow`, Ethereum. На начало месяца выбираются
10 адресов с крупнейшими покупками за предыдущие 30 дней. Копируются только будущие
покупки из разрешённого исторического состава токенов, с задержкой минимум один блок
и выходом через 24 часа. Это наша механическая версия идеи, не копия чужой торговли.

**Результат: `BLOCKED_DATA`, не отрицательный вердикт стратегии.**
Полный проверенный вход не получен, доходность не рассчитана. Ограниченный аудит
источников завершён; отсутствие бесплатной истории во всём интернете не утверждается.

## Почему swaps недостаточно

1. **Кто покупатель.** `taker`, `tx_from`, router и получатель токена не обязательно
   один субъект. Для smart wallets и агрегаторов нужна воспроизводимая атрибуция.
   Не выбираем молча удобный столбец и не сужаем Ethereum до одного DEX.
2. **Нет двойного счёта.** Событие идентифицируется по цепочке, хэшу блока,
   транзакции и log index. Экономический обмен надо отделить от промежуточных
   hops. Просто удалить всё с одинаковым tx hash тоже нельзя: одна транзакция
   может содержать несколько отдельных покупок. Выбранное определение фиксируется до результатов.
3. **Нет подглядывания.** Рейтинг использует только предыдущие 30 дней, доступные
   на начало месяца. Нельзя брать сегодняшний список успешных кошельков. Для
   USD-объёма нужны цены, известные тогда; неизвестную стоимость нельзя записать нулём.
4. **Исторический состав.** Нужны адреса, decimals, существовавшие тогда пары с
   USDC/WETH, типы активов и исчезнувшие токены. Сегодняшний каталог оставляет только
   выживших. Нормализация не должна превращать неполный список в `membership_complete=true`.
5. **Исполнение.** Чужая цена swap не является нашей котировкой в следующем блоке.
   [Uniswap Quoter](https://developers.uniswap.org/docs/sdks/v3/guides/swapping/quoting)
   позволяет моделировать конкретный размер без отправки сделки. Для исторической
   оценки нужны состояние нужного блока, маршрут и версии контрактов; текущий Quoter
   не доказывает прошлую исполнимость и не гарантирует включение в блок.
6. **Возможность выхода.** Gas, impact, token tax, ограничения transfers, снятая
   ликвидность и отсутствие обратного маршрута должны учитываться. Документация
   [Uniswap v3](https://developers.uniswap.org/docs/protocols/v3/concepts/unsupported-tokens)
   отдельно описывает несовместимость fee-on-transfer с обычным router. Созданный пул
   и прошлая покупка не доказывают возможность продажи через сутки.
7. **Порядок.** Требуются block hash, transaction index, log index, исключение
   удалённых при reorg событий и честный `available_at`. Эти поля описаны в
   [Ethereum JSON-RPC](https://ethereum.github.io/execution-apis/api/methods/eth_getLogs/).
   Архивный timestamp не является измеренной задержкой наблюдения. Задержка должна
   оставаться явно обозначенным допущением, если исторических журналов наблюдения нет.

Фиксированные периоды не сдвигаются: development 2023–2024, WF 2025, final
январь–сентябрь 2026, warmup с ноября 2022. Для расчёта требуются четыре вида входа:
`dex_swaps`, `token_universe`, `gas`, `execution_quotes`, с хэшами и полным provenance.
Неопределённость состава DEX и атрибуции адресов вынесена в аудит, а не замаскирована
автоматической заменой определения сигнала. Нынешний runtime не сертифицирован этим
документом для произвольной сырой выгрузки.

В отличие от Aave, 24-часовое удержание само по себе не исключает 30 сделок за
финальный период. Но фактическая выборка, независимость событий и концентрация
пока неизвестны. Успех по этим критериям не предполагается.

## Что проверено в коде

Выполнены семь маленьких синтетических проверок: исключение будущих покупок,
поздно опубликованных событий и данных за пределами 30 дней; ограничение рейтинга
десятью адресами с устойчивым разрешением равенства; запрет входа в тот же блок;
запрет ещё недоступной котировки; сохранение невозможного выхода как открытого риска.
Это не бэктест, не реальный sample и не доказательство правильной атрибуции сырых swaps.

20 конфигураций и 29 runtime-файлов неизменны. Все остальные 19 записей очереди
сохранены. Полный набор из 180 unit tests здесь не повторялся. Использован привязанный
к SHA снимок локальной инвентаризации v13; повторного обхода диска и чтения legacy
данных не было. `source-evidence.json` содержит заметки, не raw HTTP snapshots.

## Общая очередь

[Матрица всех 20 моделей](matrix.md) теперь отличает выполненную проверку источников
от ещё не выполненной. **Модели 7–10 пока не имеют такого аудита в этой программе.**
Нумерация модели 20 не означает, что программа завершена. Сейчас: 20 `BLOCKED_DATA`,
0 посчитанных на пригодных исторических входах, 0 принятых, 0 отвергнутых по доходности.
Для 16 моделей есть ограниченные проверки источников; это не сертификат полноты.

Следующий ограниченный шаг: provenance готовых парных котировок и funding для
`funding_carry`, `funding_cross`, `spot_dislocation`, `basis_convergence`. Сначала
manifest и статусы, не PnL закрытых экспериментов. Неполные/отклонённые прогоны
не перезапускать, старые вердикты не переносить на новые определения.

Кошельки отложены до нового пригодного входа или отдельно открытого доступа к
ключевому сервису данных. Не повторять те же поиски и не запускать постоянный collector.
Кошельки, подписи, private API, реальные операции, платные данные и расписания не использованы.
