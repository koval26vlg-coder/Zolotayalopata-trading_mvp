# Качество выборки premarket depth: 5 октября 2026

## Итог

Выполнен следующий offline-этап после согласования проекта от 29 сентября:
заморожен технический протокол и проверены пропуски, наблюдаемость обеих сторон
стакана и временная зависимость трёх структурных кандидатов текущего v6-плана.
Это не проверка торговой стратегии и не разрешение включить сбор.

**Главное ограничение: три файла не дают трёх подтверждённых независимых событий,
а достаточное покрытие по времени не гарантирует пригодную глубину стакана.**
Порог исходного плана остаётся 12 событий. Ниже него механизм и доходность не
оцениваются. Порог не заменён на «12 кластеров» или другое новое число.

## Что зафиксировано

- Пропуски остаются пропусками. Нет интерполяции, переноса последнего значения
  или подстановки нуля.
- Номинальная сетка: интервалы 20 секунд относительно открытия spot, только
  целые полуоткрытые интервалы внутри фактического окна. Для spot нет
  несуществующего pre-open стакана. Начальный неполный интервал раскрывается отдельно.
- Отсутствие попытки, ошибка запроса и непригодный ответ учитываются отдельно.
  Несколько ответов в одном интервале не увеличивают его покрытие и не дают
  права выбрать удобную цену.
- Диагностический маршрут 1%/top-25 выбирается по флагам качества для каждой
  ноги целиком: строго больше трети пригодных ответов с bid-band внутри спреда
  означает top-25. Не выбираем маршрут по доходности, отдельно для каждого
  момента или для более удобной стороны стакана.
- Для top-25 нужны хотя бы 25 уровней соответствующей стороны. Для полосы 1%
  нужны флаги отсутствия обрезания и попадания полосы внутрь спреда.
- Bid, ask и их совместная наблюдаемость показаны отдельно. Пригодный bid не
  заменяет отсутствующий ask-контроль. Неизвестный флаг не считается `false`.
- Перекрывающиеся окна и повторения одного актива объединяются в группы для
  проверки зависимости. Это метки риска, а не доказанная независимость групп.

Это **техническая диагностика**, а не скрытое изменение содержательного
контракта будущего evaluator. Она не задаёт новый порог отбраковки, не меняет
гипотезу, не сертифицирует события окончательно и не привязывается автоматически
к анализатору механизма. Старые планы, исходные данные и сентябрьские отчёты
не перезаписаны. v3-v5 не добавлены к текущей выборке v6.

## Найденное препятствие перед сбором

Замороженный `trading_mvp/src/premarket_forward_depth_watch.py` в цикле scan
вызывает `_spawn_capture` для каждого ожидающего события (строки 391-401).
Функция начиная со строки 442 использует `DETACHED_PROCESS`, отдельный процесс
и `DEVNULL`. Этот путь не обеспечивает требуемый один видимый глобальный writer.
При одновременных событиях возможно несколько отдельных capture-процессов.
Этот код в данном этапе не изменялся и не запускался.

Следующий инженерный шаг:

1. Один видимый координатор, который атомарно владеет global writer claim,
   показывает статус и остановку, проверяет quota/gate и соблюдает общий срок.
2. Одновременные события обслуживаются последовательными запросами этого
   процесса с отдельными файлами событий. Нельзя запускать ещё один writer
   или выбирать событие по увиденной доходности. Если заданную частоту нельзя
   выдержать, это раскрывается как ограничение покрытия, а не скрытый пропуск.
3. Синтетические тесты: одновременные события, уже занятый claim, ошибка сети,
   таймаут, остановка, запрет второго writer, сохранность частичных файлов.
   Затем технический refreeze без изменения гипотезы/рынков/издержек.
4. Только после этого рассматривать ограниченное возобновление накопления
   в том же scope. До включения определить общий HTTP/дисковый/runtime-бюджет.
   Сохранить предложенные контроль качества через 14 дней и предел 42 дня
   как предел расходования времени, не обещание набора выборки.

Пересмотр top-25, контрольной стороны или критерия отбора по результатам этой
диагностики был бы изменением анализа, а не техническим исправлением. Его нельзя
тихо применить к текущим событиям. Сейчас новые критерии не вводились.
