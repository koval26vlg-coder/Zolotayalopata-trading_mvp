## Что изменено

- Новый `premarket_depth_gateway.py` проводит один цикл строго через существующий `premarket_depth_dispatch`: проверка кампании, четыре каталога, резерв бюджета и не более одного подходящего пакета наблюдений через координатор. Прямого обхода бюджета нет.
- Каталоги читаются потоком с точным счётчиком байтов. Разрешены только зафиксированные Gate/OKX URL и параметры. Нет private API, redirects, proxies, автоматических повторов и сохранения raw payload. Предел полного ответа наследуется от родительского плана, а не увеличивается.
- Перед действием проверяются свежие quota/controller, хэши кода и кампании, существующий журнал, его бюджет и срок. Поле бюджета кампании обязано совпасть с журналом. Под итоговый файл отдельно оставлены 16 KiB внутри общего лимита.
- Глобальная блокировка writer наследуется от dispatcher/coordinator. Наблюдение не начинается, если его окно заканчивается после срока кампании. Незавершённый запрос не повторяется, резерв не сбрасывается.
- Новый PowerShell launcher использует видимое окно, `-Status`, `-Stop`, проверку владельца процесса и Windows Job Object. Предельная длительность будущего цикла наследуется: до 300 секунд discovery плюс до 14 400 секунд одного пакета; фактический срок кампании может только уменьшить её. Это не разрешение на такой запуск сейчас.
- Родительские coordinator/dispatch, их manifests, гипотеза и статистические критерии не изменены.

Проверка достижимости выборки должна оставаться конечной, а не превращаться в бесконечное накопление.
