# 2026-08-16 — v0 сигнал: compression-гейт недостижим, normalizer→replay заблокированы обоснованно

Задача: разобрать, почему feature normalizer на v6-данных даёт 0 событий,
и довести цепочку до фактического replay исходной slow-liquidity гипотезы.

## Диагностика (последовательно)

1. **Рассинхрон биндингов**: нормализатор читал gate-поля
   `last_slow_liquidity_history_collect_*`, указывавшие на СТАРЫЙ collect
   20260811 (забракованный), при quality от v6. Прогон с явными v6-путями
   (`E:\trading_mvp\slow-liquidity-history\...v6\`) — тот же результат.
2. **Диагностика фильтров** (прямой прогон модуля): 22 056 баров отсканировано
   по 18 рынкам; каждый бар упёрся в `context_failed` (11 315) /
   `compression_failed` (9 013) / `prior_window_gap` (1 728). До
   breakout/volume/retest-стадий не дошёл НИ ОДИН бар.
3. **Корневая причина — compression-гейт вырожден**: контракт v0 требует
   `range_width(96×1h) ≤ 1.2 × ATR(96)`. Эмпирика на точном v6-датасете:
   медиана отношения по 18 рынкам = **11.6** (мин ~4.1, макс ~28.7);
   **0 из 1 841 оценённых баров проходят порог 1.2** (и даже 4.0).
   96-барный high-low диапазон не бывает ≤1.2× одно-барного ATR ни на одном
   волатильном рынке — порог математически недостиж fuera pegged-актива.

## Вердикт цепочки

- Сигнал v0 `slow_liquidity_regime_breakout_retest_v0` как записан даёт
  **ноль событий на любых реалистичных данных** (не только v6: тот же
  результат был на старом collect 20260811).
- «Фактический replay исходной гипотезы» при 0 событий — пустой бэктест
  без единого трейда; конвейер корректно блокирует replay
  (`min_independent_events=100` в замороженном validation contract;
  replay-инструмент требует fixed-v1 READY-решение).
- Отсюда: **v0 в текущей формулировке неисполним**. Это свойство
  определения сигнала, а не данных. Терминальный REJECT/переопределение —
  решение пользователя (изменение signal definition = критический
  checkpoint по standing policy).
